# Настройка и обновление Supabase

Приложение использует Supabase для каталога, контактов, медиа и общих сессий единственного администратора. Без параметров Supabase каталог может работать с localStorage и IndexedDB; локальный вход в админку разрешается отдельно и только для разработки.

## 1. Подготовить проект

В [Supabase Dashboard](https://supabase.com/dashboard) создайте проект или откройте существующий. Если он приостановлен, возобновите его и дождитесь готовности. Для приложения нужен серверный API-ключ, а не пароль PostgreSQL. Регион выбирайте с учётом аудитории; доступность сайта и загрузок с реального подключения администратора в Китае проверяется отдельно.

Перед обновлением существующей базы сохраните резервную копию. Миграции ниже не удаляют объявления, контакты или файлы и не подставляют демонстрационные данные.

## 2. Выполнить миграции

В **SQL Editor → New query** последовательно выполните содержимое файлов:

1. `supabase/migrations/202609140001_catalog.sql` — таблицы `vehicles`, `site_settings`, версия объявления для защиты от одновременных правок и бакет `vehicle-media`.
2. `supabase/migrations/202609150001_vehicle_integrity.sql` — строгая проверка JSON-документа и безопасного значения версии, в том числе для существующей таблицы.
3. `supabase/migrations/202609150003_admin_auth.sql` — таблицы `admin_sessions`, `admin_login_attempts` и атомарное резервирование попыток входа.

Если первая миграция уже применялась, обновление требует выполнения двух следующих. Их можно запустить повторно. Для работы новой авторизации третья миграция обязательна: при отсутствии таблиц или недоступности базы вход закрывается.

Миграция целостности добавляет ограничения как `NOT VALID`: все новые записи и изменения сразу проверяются, а старые записи сохраняются для разбора. Завершающий запрос возвращает ID записей, не соответствующих новым требованиям. Проверьте каждый такой ID и исправьте данные осознанно; автоматического обрезания текста, округления цены или удаления нет. Записи с некорректными известными полями не попадают в публичный каталог, лишние поля старых документов не возвращаются через публичный API.

Когда диагностический запрос не возвращает строк, завершите проверку существующих данных:

```sql
alter table public.vehicles validate constraint vehicle_data_valid;
alter table public.vehicles validate constraint vehicle_version_safe_integer;
```

Таблицы закрыты для браузерных ролей `anon` и `authenticated`. Приложение обращается к ним через сервер Next.js. В таблице сессий хранится хеш случайного токена и версия учётных данных; пароли в базу не записываются. Supabase Auth для этого входа не используется.

Бакет публичный, поскольку медиа показываются посетителям. Загрузка разрешается сервером после проверки администратора и выполняется по подписанному URL. Разрешены JPG, PNG, WebP, AVIF, MP4, WebM, MOV. Приложение проверяет заявленный размер: фото до 15 МБ, видео до 50 МБ; лимит всего бакета — 50 МБ на объект. Проверка заявленного размера не доказывает фактический размер или содержимое файла. Отдельное ограничение бакета в 15 МБ для фото и проверка содержимого файла на сервере в текущей схеме отсутствуют.

## 3. Настроить сервер

Скопируйте `.env.example` в `.env.local`, если этого файла ещё нет. Не перезаписывайте существующие секреты. Заполните:

```dotenv
SUPABASE_URL=https://PROJECT_REF.supabase.co
SUPABASE_SECRET_KEY=sb_secret_...
ADMIN_SESSION_SECRET=случайное_значение_не_короче_32_символов
ADMIN_PASSWORD=уникальный_сильный_пароль
ADMIN_LOCAL_AUTH=false
```

Project URL находится в **Connect** / настройках проекта; серверный ключ — **Settings → API Keys → Secret keys**. Нужен Secret key, а не Publishable key. Не добавляйте префикс `NEXT_PUBLIC_` к секретам, не отправляйте их в чат и не коммитьте. `.env.local` исключён из Git.

Логин — `admin`. Пароль обязателен: от 16 до 256 символов, как минимум одна буква, цифра и знак, не являющийся пробелом. Пустой или слабый пароль отключает вход; пароля по умолчанию нет, `123456!` больше не подходит. Случайный секрет сессий можно сгенерировать локально командой:

```powershell
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

На всех экземплярах приложения должны быть одинаковые пароль и секрет сессий. После изменения переменных перезапустите сервер; при размещении задайте их в настройках хостинга и выполните новое развёртывание. Смена пароля или секрета делает прежние сессии недействительными. Выход удаляет сессию из общей базы; копия прежней cookie больше не даёт доступ. Сессия действует до 12 часов. При ошибке базы выход сообщает о неудаче: повторите его после восстановления соединения.

Попытки входа ограничены общими счётчиками в PostgreSQL: до 5 попыток с одного источника и до 30 попыток для `admin` за 15 минут. Учитываются и успешные попытки; запросы после исчерпания лимита не продлевают блокировку. Без настроенного доверенного IP-заголовка все запросы считаются одним источником — 5 попыток за 15 минут суммарно.

Для размещения за обратным прокси доступны необязательные параметры:

```dotenv
# Точные внешние origin через запятую, без пути и завершающего слеша.
ADMIN_ALLOWED_ORIGINS=https://motors.example
# Только заголовок, который ваш прокси гарантированно перезаписывает.
ADMIN_TRUSTED_IP_HEADER=
```

`ADMIN_ALLOWED_ORIGINS` задаёт разрешённые адреса для запросов изменения данных, если внешний адрес отличается от адреса, видимого сервером. Без него проверяются origin и Host, включая нормализацию loopback-адресов Next.js. Заголовки Forwarded сами по себе доверия не дают.

Задавайте `ADMIN_TRUSTED_IP_HEADER` только после проверки конфигурации прокси: клиент не должен иметь возможность подставить свой IP или обратиться к серверу в обход прокси. Произвольный `x-forwarded-for` по умолчанию игнорируется.

Для разработки без Supabase оставьте оба параметра Supabase пустыми и явно включите `ADMIN_LOCAL_AUTH=true`. Нужен тот же сильный пароль. Сессии и лимиты в этом режиме хранятся в памяти одного процесса, перезапуск завершает все сеансы. В production этот флаг не разрешает локальную авторизацию. Для безопасного сохранения localStorage между вкладками нужны Web Locks и HTTPS либо localhost; без Web Locks запись отклоняется с сообщением.

## 4. Перенести объявления из браузера

Откройте админку в том браузере и по тому адресу, где добавляли автомобили. `localhost` и `127.0.0.1`, разные порты и профили имеют отдельные хранилища.

1. В **Настройки → Хранение данных** дождитесь подтверждения подключения.
2. Нажмите **Подготовить импорт из браузера** и проверьте список.
3. При необходимости отметьте замену контактов; по умолчанию они не перезаписываются.
4. Нажмите **Начать импорт** и держите вкладку открытой до завершения.

Локальные фото и видео загружаются в Storage, внешние ссылки остаются ссылками. При отсутствии файла или нарушении ограничений импорт останавливается с ошибкой. Уже перенесённые объявления сохраняются; повторный запуск пропускает существующие ID и не перезаписывает их. Локальные оригиналы не удаляются.

Новые ограничения действуют и при импорте: цена — целое число от 1 до 100 000 000 USD; год — целое число от 2000 до 2035; текстовые поля — до 80 символов, комплектация до 160, город до 120, VIN до 64; до 100 фотографий. RU/CN сохраняются отдельно. Если старые данные не проходят проверку, сначала разберите ошибку и сохраните копию исходных данных, затем исправьте соответствующие поля.

После подключения пустой облачный каталог остаётся пустым. При сбое Supabase приложение не переключается на локальные данные. Невалидные локальные данные также не перезаписываются автоматически.

## 5. Проверить после обновления

Проверьте вход новым паролем, редактирование RU/CN, цену, контакты и медиа на отдельном тестовом объявлении. После выхода прежняя сессия не должна разрешать запись. Не используйте действующие объявления для разрушительных проверок.

Вкладки обновляются при возврате к ним и каждые 30 секунд, а вкладки одного браузера дополнительно уведомляют друг друга. Одновременные обновления объединяются в один запрос. Запоздавший ответ не должен отменять свежую сохранённую правку. Конфликт редактирования автомобиля или контактов показывает ошибку вместо перезаписи чужих изменений; это действует и в localStorage.

Общий срок операции с API на сервере — 20 секунд, на клиенте — 25 секунд; загрузка каждого файла ограничена 120 секундами. Чтение тела JSON ограничено 10 секундами и 256 000 байтами. Автоматические повторы запросов к PostgREST отключены. После сбоя обновления посетителю остаётся последняя успешно загруженная версия и видимое сообщение с повторной попыткой. После таймаута записи сначала обновите страницу и проверьте результат: отмена ожидания не гарантирует отмену уже выполненного изменения в базе.

Удаление объявления удаляет запись каталога; медиа автоматически не удаляются, поскольку на них могут ссылаться другие объявления. Неиспользуемые файлы после проверки ссылок очищаются вручную. Подписанные загрузки, фактические MIME/размеры файлов, поведение при прерывании импорта и доступность из Китая требуют отдельной проверки на инфраструктуре размещения.

Перевод пользовательского текста не выполняется автоматически. Для отображения описания на обоих языках заполняйте обе версии объявления.

## Проверки в репозитории

`npm test` запускает регрессионные проверки валидации, авторизации, SQL-ограничений, конфликтов и сетевых ошибок. SQL выполняется в изолированном PGlite, а HTTP к Supabase и контекст Next.js в тестах подменены. Это не заменяет проверку реального Supabase и полного сценария в браузере. `npm run lint` и `npm run build` проверяют код и сборку.

Подробности исправлений и границы проверки: [SECURITY_FIXES.md](SECURITY_FIXES.md). Исходный аудит сохранён отдельно в `AUDIT_REPORT.md` и `tests/audit/`.
